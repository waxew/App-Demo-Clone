# AS

برنامهٔ مدیریت کسب‌وکار، مشتری، فروش، فاکتور، امور مالی، کارگاه و اسناد؛ با رابط فارسی RTL و اجرای آفلاین در Android WebView.

> وضعیت فعلی: این مخزن عمدتاً شامل لایهٔ WebView/HTML/JavaScript و دارایی‌های برنامه است. سورس کامل Android wrapper و فایل‌های قابل‌ساخت Gradle/Kotlin/Java در نسخهٔ فعلی موجود نیستند.

## معرفی

AS چرخهٔ کاری زیر را پوشش می‌دهد:

`مشتری ← کالا/خدمت ← خرید/فروش ← فاکتور ← پرداخت/چک ← گزارش و آرشیو`

برنامه برای کار آفلاین طراحی شده و داده‌ها، تنظیمات و دارایی‌های بصری را در storage محلی/WebView نگه می‌دارد. خروجی فاکتور به‌صورت پیش‌نمایش HTML، تصویر، PDF، چاپ یا ارسال آماده می‌شود.

## ساختار پروژه

```text
app/src/main/assets/
├── index.html                         # Shell، UI، Router، State و منطق دامنه
├── product_core_v3962.js              # مدل داده و منطق پایه
├── product_v39*.js                    # featureها، اصلاحات و مرحله‌های توسعه
├── document_engine_v2.js              # موتور سند و خروجی
├── invoice_full_shell_data_v3970.js   # داده‌های shell فاکتور
├── invoice_templates_v3970.js         # قالب‌های فاکتور
├── reservation_signature_v39432.js    # منطق رزرو/امضا
├── invoice_*                          # قالب‌ها، shellها و previewها
├── invoice_identity_presets/          # مهر، امضا و هویت بصری
└── ...

app/src/main/res/drawable/             # لوگوها و آیکون‌ها
binary_reference/                      # باینری/مرجع APK، نه سورس build
AS_PROJECT_ARCHITECTURE_REPORT.md     # گزارش تفصیلی معماری
```

## معماری اجرایی

```text
Android WebView
      ↓
index.html (Shell / Router / UI / State)
      ↓
Feature modules + product_core
      ↓
Storage محلی/امن و Native Bridge
      ↓
Backup / Restore / Recovery

فاکتور و سند → Preview → PNG / PDF / Print / Share
```

`index.html` با `state.tab` و handlerهای `data-action` صفحه‌ها را عوض می‌کند. تابع‌های اصلی مانند `renderApp`، `setTab` و `saveData` چرخهٔ رندر، ناوبری و ذخیره‌سازی را کنترل می‌کنند. ترتیب بارگذاری فایل‌های JavaScript نسخه‌دار بخشی از قرارداد فعلی برنامه است.

## صفحه‌ها و قابلیت‌ها

- **خانه:** خلاصهٔ وضعیت، شاخص‌ها و میانبرهای عملیاتی.
- **مشتریان:** فهرست، جست‌وجو، وضعیت بدهکار/بستانکار، پروفایل، فعالیت و پیگیری.
- **فاکتور:** انتخاب مشتری، اقلام، محاسبه، پرداخت، قالب، مهر و امضا.
- **خریدها و محصولات:** کالا/خدمت، خرید، موجودی و داده‌های فروش.
- **امور مالی:** پرداخت‌ها، بدهی، بستانکاری، چک و خلاصهٔ مالی.
- **کارگاه/رزرو/اجرا:** سفارش کار، خدمات، رزرو و امضا.
- **گزارش‌ها و پورتفولیو:** گزارش عملکرد، مالی و سوابق.
- **پشتیبان‌گیری:** export، restore، recovery package، backup چندنسخه‌ای و مهاجرت.
- **سطل زباله:** نگهداری و پاک‌سازی داده‌های حذف‌شده.
- **تنظیمات و دارایی‌ها:** اطلاعات کسب‌وکار، فونت، لوگو، قالب، مهر و امضا.
- **RAL کلاسیک:** کاتالوگ/انتخاب رنگ.

## UX و UI

- mobile-first با عرض shell حدود ۴۳۰ پیکسل
- RTL و متن فارسی
- bottom navigation ثابت و topbar چسبان
- کارت‌های گرد، فرم‌های تک‌ستونه، modalهای پایین صفحه و toast
- رنگ‌بندی سرمه‌ای، سبز، طلایی و پس‌زمینهٔ روشن
- فاکتور responsive با حالت چاپ مستقل
- انتخاب دارایی فعال برای preview، عکس، PDF و ارسال

## داده، ذخیره‌سازی و Native Bridge

داده‌ها در state/مدل JavaScript ساخته و از طریق wrapperهای storage ذخیره می‌شوند. تنظیمات، مشتریان، محصولات، draft فاکتور، دارایی‌های تصویری و سوابق backup در این چرخه قرار دارند.

عملیات فایل، اشتراک‌گذاری، رمزنگاری یا ذخیره‌سازی امن ممکن است از طریق Android bridge انجام شوند. چون سورس wrapper اندروید در نسخهٔ فعلی وجود ندارد، قرارداد دقیق bridge باید قبل از تغییرات بزرگ استخراج و مستند شود. تغییر نام توابع یا کلیدهای storage بدون هماهنگ‌سازی wrapper می‌تواند backup، share یا secure storage را مختل کند.

- حذف duplicateها و مشخص‌کردن ترتیب بارگذاری

### AS 1.3 — تکمیل تجربهٔ کسب‌وکار

- گردش‌کار پیش‌فاکتور تا فاکتور نهایی
- پرداخت‌های چندمرحله‌ای و تسویهٔ بدهی
- مدیریت موجودی و هشدار کمبود کالا
- فیلتر و جست‌وجوی پیشرفته
- گزارش سود، فروش و مانده‌حساب

### AS 1.4 — اسناد و خروجی حرفه‌ای

- مدیریت نسخهٔ قالب‌ها، لوگوها، مهرها و امضاها
- اشتراک‌گذاری امن و قابل‌ردیابی

### AS 2.0 — زیرساخت قابل‌ساخت
